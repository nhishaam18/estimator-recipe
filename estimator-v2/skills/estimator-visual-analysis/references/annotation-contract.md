# Component-level image annotation

Draw four readable layers at the original image dimensions, without a description sidebar: solid blue sections (R01…), dashed red nested composite items (I01…), dashed green navigation/footer groups (G01…), and dashed purple owned actions (CTA01…). Include each visible icon-and-copy tile, card, service row, slider item and genuine widget. A group heading and its single link list can share one boundary. Ordinary headings, paragraphs, portraits, icons, inline prose links and individual ordinary navigation/footer links remain unboxed.

Separate reusable family definitions from unique route/viewport occurrences. Preserve true parent/child units even if both have inner level or identical geometric bounds. Repeated Slider Items or Team Cards are occurrences of a family, not automatically unique implementation types. Similar names/classes alone do not prove identical behavior or styling.

The model proposes labels and screenshot-relative boxes. Tile merging converts them to document pixels. Saved DOM measurements support matching and deterministic boundary refinement; they do not make model-selected boxes exact measured source-component identities. Retain original model/rectangle evidence and uncertainties. Actual content inside raster illustrations must not become detected live UI.

The classifier labels detections component, content, part or uncertain. Only validated components enter the implementation family list. A separate deterministic annotation selector adds DOM-backed nested composites, groups and owned action boundaries without promoting them to implementation families or CMS types. All excluded/uncertain findings remain in JSON and overview accounting. Missing/ambiguous DOM, malformed geometry, cycles and unsupported ownership remain unresolved rather than invented. Rules use structural/semantic evidence, without website-specific allowlists.

A root anchor may be a full composite card: HTML tag choice does not decide its role. SVG/icon plus independently grouped title and supporting copy can establish a linked tile even when text uses divs. Decorative SVG path differences do not establish different component structures. Do not split such a tile into icon/link primitives, or treat a simple single-label icon link as a card. Native analysis must account for these children explicitly. DOM-recovered item boundaries missing from the native inventory generate quality findings for bounded reanalysis, rather than being silently accepted as CMS families.

A section action belongs to the section; an item action belongs to its item. A whole-card clickable region retains action semantics within its single item boundary, without a coincident duplicate action box; smaller inner controls can have separate boxes. The drawing is a navigation aid, not the complete element inventory and not a CMS schema. Rich text continues to own ordinary article material; genuine embedded widgets retain their own boundaries and controls.

Store JSON beside each annotated PNG. Items retain stable internal IDs, capture-local readable labels, kind, name, selector, nearest owner, source detection when available, annotation-only status and source/visible geometry. `discovery.json.annotationItems` joins these across captures. Extra boxes do not create extra CMS types. Reports remain more detailed than the image and retain fields, exact text, assets, typography and styles for unboxed elements.

Capture uses CSS-pixel screenshots at scale 1. Preserve full rectangles separately from visible bounds, clipping against image edges and rectangular overflow ancestors. Omit recorded hidden/fully clipped nodes; clip partial slider items. This does not establish pixel legibility, occlusion or rounded clipping. Legacy bounds without complete visibility evidence emit warnings and use only available saved overflow evidence; retain the warning unless a separately diagnosed supported recovery is warranted. Hash-bind ledgers to screenshot, HTML, rectangles and detections; regenerate after changes. Limits of 50,000 recovery nodes and 1,500 annotations emit explicit warnings. This pass makes no extra model call, navigation or interaction probe.

Use saved raw screenshots and derivatives from the same capture. Missing DOM for supplied screenshot-only material requires explicit evidence gaps/manual measured image records; this runtime accepts URL capture evidence and must not fabricate DOM selectors for an uploaded screenshot. Interaction states and screenshot-only annotation are not newly implemented by this extraction.

Consent acceptance/removal and unobstructed source-image inspection precede detection acceptance. Visual Analysis opens every assigned source tile and flags obstructions or unclear boundaries. No automatic paired-region second pass runs in this recipe. Deterministic quality checks and explicit targeted source-tile corrections remain; script validity cannot certify visual completeness. Preserve unresolved findings and provisional reporting without a human approval stop.
