# Script-controlled execution, Kajoo model boundary

Two agents only: Estimator runs packaged commands directly; Visual Analysis interprets its assigned screenshot. No Developer execution agent or agent-per-command handoffs. Scripts control grouping, sampling, capture, packet preparation, serial imports, annotation drawing, refinement and report generation. Never replace them with ad-hoc programs or model reasoning. Read the advertised estimator entry once to stage resources; supporting references are conditional reads.

1. Ask for a website URL if absent. Bootstrap once from the staged estimator skill; immediately preserve runtime/runsDir/setup/verification receipt paths. Subsequent commands use the literal dependency-bearing runtime, never /mnt/skills. Reuse verified setup and exact-scope saved discovery on resume.
2. Always call Firecrawl Map for a new scope. Save only the complete URL list as {"links":["https://..."]}; omit title/name/description. Preserve every returned URL in order, including duplicates, for script normalization. If the connector supplies a real result file, run map-urls --file <actual file> --output <new urls.json> without reading its full content. Inline-only output has no implicit file handle: write the URL-only JSON once from the actual response, never reconstruct missing URLs or re-Map due to context clearing. Initial MCP response tokens are still incurred. Use flow discover-plan to group it; show EVERY group ID/pattern/count/suggestion and collect explicit quantities including zero/all. Tool approval is not sampling consent.
3. Save user quotas keyed by group ID. Use flow prepare with the reviewed planFingerprint. One foreground command freezes the random sample, initializes/reuses its run, captures serially for four minutes and reserves at most two packets. Scripts create immutable job files/checkpoints. Partial means a new flow advance step on the SAME runDir, never bootstrap/init/resample again. See [flow contract](references/job-contract.md).
4. A new saved reservation/flow receipt is the dispatch intent. Launch at most TWO Visual Analysis run-agent calls in the SAME assistant tool-call batch. Pass only runDir/requestId/promptFile/image/resultFile; omit runId/history/background. Workers write separate assigned drafts. End the turn and wait for automatic results, no polling. If parallel dispatch is unavailable, run the two assigned packets serially. Replayed/reused reservations require actual platform reconciliation; never redispatch on replay.
5. Save actual platform outcomes as a bare array, max two objects: requestId, jobId, status, optional concise reason. Never {jobs:[...]}, platformRunId, receipt, ready or worker-proclaimed status. Run flow settle-batch directly. Scripts validate/import serially, retain valid siblings and reserve next work only after successful nonempty settlement. Repeat the returned action without per-command narration, extra status calls or another execution agent.
6. When detection is complete, run flow report. Scripts draw annotations and assemble reports. Read deterministic quality findings; NO automatic paired raw/annotated-region second pass. For estimates, run flow prepare-estimates once, then use `cest.mjs estimate-next`, read only the assigned packet/reports, save its result, and run `estimate-record`. Repeat until ready-to-finalize and run `estimate-finish`. The scripts own progress, source binding and assembly. Do not read the full inventory or earlier chat to infer progress. Preserve coverage and parent/child exclusions. Do not rewrite reports from raw evidence yourself.
7. Publish actual saved outputs with available artifact tools. Deliver verified links, status, counts, effort range and material gaps. Sitecore defaults unless explicitly overridden; rate/currency must be supplied. No phases/tasks, app, CMS implementation, direct model/provider API or deployment. Stop at reports and estimates.

## Resume and failures

Identifiable components with missing rendered parts are successful detections with nonblocking gaps, for ALL component types. Import them and continue reports/estimates; no automatic recapture, corrective worker, user question or retry solely for those gaps. Keep warnings and missing-appearance uncertainty. A genuine screenshot-access/overlay, source, schema or geometry failure is still blocking; gaps never bypass validation.

Keep runtime/verification paths, run/plan identity, quotas, latest flow checkpoint/receipt, active batch/request/job IDs and blockers in small durable state. Checkpoints, immutable receipts and source files are authoritative; summaries must preserve their exact paths. Never carry screenshots, full Map output, DOM/styles, detections or reports through the coordination loop. Read relevant reports only for consolidation/estimates. Summarization does not remove fixed platform overhead.

Blocked/needs-diagnosis stops automatic advancement. Read only named error/command logs; verify actual entrypoint and replay status before diagnosis. Cached receipts describe the original attempt. One supported one-route recover-capture after settlement handles failed/obstructed/lazy-incomplete evidence; changed source can require affected-page packets again. Preserve unchanged imports and other pages. Use explicit script reservations for at most two visual corrections or one diagnosed transient retry. No ad-hoc diagnostics/script editing, repeated repair jobs, automatic lock/stop deletion or full-run restart. Unknown execution ownership holds work; cancelled work needs resumed user authorization. Report remaining gaps without forcing passing quality or dropping components.

For an oversized read, do not repeat it or read conversation-history JSONL. Use node <runtime>/scripts/cest.mjs read-evidence --file <named checkpoint/error file> --pointer /neededField --limit 4000. Omit pointer for text; use returned nextOffset only when more of that specific evidence is necessary. Output is character-bounded even for one long JSON line. Never page through full history or bulk raw evidence. Recover from saved checkpoint/packet paths.
