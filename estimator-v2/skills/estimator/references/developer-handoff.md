# Developer reading contract

The estimating agent supplies the exact run folder or published artifact references. Begin at export/delivery-manifest.json and export/report.md, then quality.json, build-list.md and estimates.md. Each numbered file under export/components/ describes the component's purpose, proposed CMS-neutral fields and ordered child components, occurrence content, measured appearance/typography, behavior limits, gaps and evidence links. Follow child reports; use matching .evidence.md appendices and discovery.json for exact selectors, geometry, styles and assets.

Map each field to the target CMS only after loading the destination developer's CMS guidelines. A component family shared across pages does not imply one globally shared content item. Report proposals are not required/localized/editor constraints. Missing style measurements are gaps, not permission to copy a parent's CSS. Font-family declarations do not verify downloaded font files or licensing. Annotation boxes and build families serve different purposes.

This recipe stops at reports and provisional estimates. It does not create a developer agent, send another agent a message, generate React, deploy an application or mutate a CMS.


Sitecore is the default target for implementation estimates unless the user explicitly names another CMS. Keep the component evidence portable; an estimation default does not authorize schema generation, CMS writes or an invented Sitecore product/version.
