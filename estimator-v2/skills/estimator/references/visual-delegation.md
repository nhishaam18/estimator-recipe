# Developer visual batch contract

Developer does not delegate or inspect images. Orchestrator launches Visual Analysis using saved reservations, omitting runId per independent packet. See [Developer assignments](developer-jobs.md).

Run batch --run <folder> after detection preparation. Return batchId, batchFile and at most two packet descriptors (requestId, promptFile, image, resultFile). They can be different overlapping tiles from one screenshot or tiles from different pages. Each attempt has a unique output path. A reused active reservation is for reconciliation, never duplicate dispatch.

Orchestrator supplies only packet paths/IDs, saves dispatch intent and awaits automatic results. Developer receives verified platform job IDs/statuses in a small outcomes file and uses settle-batch to import completed assigned drafts serially. A model-ready sentence is not platform completion or valid evidence. Unknown/running jobs retain their slots; failed results never discard successful siblings. Workers do not edit manifests, merged detections, annotations or Build Lists.

After diagnosis explicitly reserve a retry or correction. Maximum one transient retry or two visual corrections per request. Never overwrite archived originals, overlap active work, clear circuit breakers automatically or restart the whole run to fix JSON. Fix genuine popup preparation and recapture only the affected authorized route after active jobs are reconciled.

No paired raw/annotated-region jobs run. Primary source-tile inspection, deterministic checks and focused source-tile corrections remain. Geometry, ownership, cards/slider items/hero composites, CTA rules, DOM refinement, unique-family counting and complete field/style reports remain unchanged. Unresolved findings remain provisional, not forced passing results.
