# Consolidation and implementation estimates

An identifiable component with nonblocking rendering gaps remains in the unique list and estimate. Record uncertainty for its unverified parts; do not request recapture or another model pass solely for missing images/text/icons. Existing source-bound report evidence, parent/child exclusions and unique-count rules still apply.

Follow [context budget](context-budget.md). Read each native prompt/request once. Process relevant component reports in small batches and save draft decisions/completed keys. After resume reopen missing or ambiguous evidence, not completed reports. Compact execution preserves full component/child/style coverage.

Consolidation sends no HTTP request. consolidate saves consolidation/request.json and prompt.txt. Read them with Kajoo's model; reply with the exact requestId and groups of existing temporary IDs, name and reason. Only same-level equivalent units may group. Scripts reject stale inventory, duplicate/unknown IDs, mixed implementation types and known parent/child merges. Imported groups retain original source keys and aliases. Rebuild report after imports so family names and links match. reset-merges retains manual groups. Native consolidation is text-based; consult saved component reports when ambiguous and keep differences separate. It does not establish visual equivalence.

estimate saves estimation/request.json, prompt.txt and script-owned progress.json with the exact current unique build keys, target and optional user hourly rate. Then call `estimate-next --run <folder>` (default five items; `--size` allows one to ten, fixed for this request). Read only its saved packet and the assigned component reports, linked child reports, evidence appendices and relevant quality findings. Save one JSON result containing the packet's requestId and batchId, a nonempty assumptions array, and exactly the assigned items: key, lowHours, likelyHours, highHours, rationale and exclusions array. Run `estimate-record --run <folder> --result-file <absolute JSON path>`; repeat `estimate-next` until it returns ready-to-finalize, then run `estimate-finish --run <folder>`. Ranges must be finite, nonnegative and ordered. They express Kajoo model judgment, not measured historical productivity.

Count definition work once. Do not multiply by instances or pages. If a Team Grid embeds Team Cards, Grid hours cover grid structure/integration while Card hours cover Card implementation; shared CTA implementation is counted once. Include component modeling, desktop rendering and component QA; disclose project setup, integrations, content entry/migration, deployment, untested interactions and licensing as exclusions unless separately scoped. This recipe does not generate or implement code.

Only a user-supplied rate via --rate and --currency yields monetary totals. Never copy a model-suggested rate into those options. Otherwise monetary totals are null and hours remain usable. The target CMS defaults to Sitecore without asking. Only an explicit user CMS/stack choice overrides it with --target. Do not infer a Sitecore product/version or specific schema; record those unprovided details as estimation uncertainty. Mobile implementation is outside scope.

import-estimates validates complete inventory coverage and source binding. Inventory changes invalidate old estimates and replace their Markdown with a stale notice; prepare/import fresh estimates after merging/refinement. Uncertain evidence is explicitly provisional. Model API usage is available only through Kajoo traces and is not part of component labor pricing.


The script saves fragments and completed keys in estimation/progress.json and validates full coverage on finish. On resume, call estimate-next against the saved run; do not read conversation-history JSONL or infer progress from chat. Read one assigned packet at a time, not the full request or all component reports. A failed read is diagnosed once using a named file and bounded read; do not loop over the same missing path or oversized line. After recording a batch, retain only the run path and returned progress count in coordination context. No additional agent is launched.
